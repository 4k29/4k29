# Correction to the Round34 context explanation

The archived Round34 RESULTS.md says the context256 limit makes some outputs incomplete. The new read-only fixed-prefix-context-audit.json resolves the actual budget for these42 fixed inputs: original17 input15–35, daily12 input13–39, native8 input39–57, source5 input25–44 tokens. Every one can generate the full configured maximum192 tokens within context256. Thus, for these measured outputs, truncation at the configured generation maximum192 must be distinguished from hitting the context window256. The old wording did not make this distinction and is inaccurate if read as claiming the256 window was actually exhausted by these42 generations.

The old frozen Round34 files remain byte-identical because they are pinned comparison inputs of the live Round35 trial. This correction adds evidence without silently rewriting that history. It changes neither outputs, judgments, checkpoints, learning conditions nor either round's acceptance gates. It does not establish that context256 is adequate for every task or training example. Short-range semantic failures already occurring before either limit still cannot be explained solely by extending output length.
