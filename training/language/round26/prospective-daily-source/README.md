# Prospective everyday-conversation source — NOT used by R26

The user identified everyday Japanese conversation as the actual target genre. This directory preserves candidate-source provenance and TRAIN-only audit evidence while R26 keeps its original frozen corpus and configuration.

Source: [nu-dialogue/real-persona-chat](https://github.com/nu-dialogue/real-persona-chat/tree/28d0b6b3865b29cabc26c230a2db37cdf315e937), commit 28d0b6b3865b29cabc26c230a2db37cdf315e937. Human collection reference: [Yamashita et al., PACLIC 2023](https://aclanthology.org/2023.paclic-1.85/). Corpus license: CC BY-SA 4.0, preserved in real-persona-chat-LICENSE. Metadata/profiles and the repository's separate LLM-system logs are not training targets; the latter were not extracted or parsed.

Speaker folds were fixed using opaque speaker IDs before acquiring utterances: 187 assigned TRAIN, 23 development, 23 reserved TEST. Only dialogues whose two speakers share a fold are retained; cross-fold dialogues are excluded. The exposed README example dialogue 1 is excluded. Actual raw candidates: 8,992 TRAIN dialogues, 99 development, 99 reserved TEST, 4,392 cross-fold exclusions and one public-example exclusion. TRAIN has 185 observed speakers; two assigned TRAIN speakers have no retained dialogue.

The acquisition manifest (`human-source-acquisition.json.gz`) stores all original file SHA256/Git blob SHA1 and folds. No raw utterance text is committed here. Raw files remain in /workspace/daily-conversation-source-audit/human-only-raw, isolated by fold. No tokenizer, model loss or generation has accessed reserved text. The TRAIN-only audit used 270,388 utterances and 6,181,551 Unicode code points (Python len); this subset/unit is not the README's full-corpus statistic. It found zero empty/control-character utterances, five excess exact duplicate dialogues, and twelve dialogues containing original redaction markers. No source text has been rewritten or filtered yet.

## Reproduction of the actual acquisition and audit

These two scripts are exact execution receipts, including the original cache path. Create /workspace/daily-conversation-source-audit, decompress the two .json.gz metadata files to their original .json names (gzip -d or Python gzip.decompress; raw/gzip SHAs are in source-metadata-hashes.json), copy those JSON files, the remaining JSON metadata and real-persona-chat-LICENSE from this directory there, then run acquire-as-executed.py and audit-train-as-executed.py. Acquisition fetches the pinned archive and verifies each human dialogue against its Git blob SHA before writing fold-isolated raw files. It never extracts/parses the separate LLM logs. SHA256 values for the scripts and archive are in the decompressed human-source-acquisition.json; audit-train-as-executed.py loads TRAIN only. No model updates occur in either script.

Before any later training: audit source duplicates and cross-fold leakage, define deterministic serialization/filtering, bind code/data/license SHAs to a new one-factor round policy, and decide against completed R26 results. These candidates are not adopted, not instruction-tuning success, and not evidence of daily-chat generation ability. No R27 training has started.
