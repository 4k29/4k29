# 固定checkpoint診断 — 文脈反応はあるが、内容予測と全文生成は未熟

R46 selected9500の既存raw FP32重みを固定。model/state・checkpointファイル・Torch RNGは前後一致、optimizer構築0/更新0。R25正式anchor、R48全量集中CEのNo-Go、既存17/13/9 gate/Pareto/実用guard/公開model/siteは維持し、マージも行っていない。本診断で日本語能力が改善したという主張はない。

## 実施範囲と入力の固定

主対象は既存TRAIN標本12件（RP/JMRD各6）と露出済DEV13件（RP8、MRMP5）。完全な原文次発話を、真正履歴・別会話の同長履歴・BOSのみで比較し、75全文/全tokenを保存。真正/別履歴のownBPE token数は全件一致、最大prefix57token、gold最大104tokenで、cropやrolling contextは不要だった。

別枠で、補助学習に使った既存TRAIN1024組/403文書を3条件でteacher forcing評価。全体3147 TF rows。このpoolは語彙anchorで選ばれ、重み学習済みで、一般化評価ではない。主TRAIN12件はpoolと文書/発話対の重複0だが、通常の主学習TRAINである。DEVも繰返し露出した既存資料で、封印TESTを新規使用していない。

source SHA・発話ordinal・speaker・license/URLを保持。4つの同話題donor候補をモデル出力前の原文確認で除外し、その理由/原典/順位を保存した。単なる別文書でも同じ話題になり得るためで、学習資料のfilterではない。別履歴でも汎用goldが適切な場合はあり、無関係履歴を誤答ラベルにはしない。BOSのみは絶対位置も変わるため、文脈効果の主比較は同長の真正対別履歴。

## 2. 内容語の予測

出力前に20caseの41 lexical/inflected spansを手動固定。ownBPE両端が整列するのは38span。canonical ID列のteacher-top1完全一致は38中0。DEVのspan平均NLLは真正5.259/別5.536で改善するが、原文固有の内容をmodeとして安定再現できていない。

これは語の意味理解正答率0%という意味ではない。語や返答は一意でなく、長い複合語/映画の固有事実/本人しか知らない経験/入力にない@話者名も含む。未整列3spanは境界外を含むtouched-token指標と区別し、完全語一致を定義しない。

主対象全510gold tokenのtop1一致は149（29.22%）。出力後の探索的byte-prefix互換チェックでは152へ3tokenだけ増えた。多くの誤差を単なる別BPE表現だけで説明する根拠は弱いが、Tokenizer全般の問題を否定した検証ではない。元の指標は置き換えていない。

## 3. 正解履歴と自己生成履歴

原文gold途中までを与えるTFより、自己生成履歴に置換した同じgoldへのsurprisalは大きい。利用可能な同一位置のtoken加重平均で、RP DEVは112tokenのTF3.482→自己履歴9.771、MRMP DEVは39tokenの5.828→9.122だった。第1節のcase平均とは重み付けも、EOSまでに使える位置集合も異なる。ただし分岐後はgoldと生成の意味が対応しないので、これはcounterfactual感度であり「日本語誤答率」ではない。異なる自然な返答でも上昇する。

真正条件25件のうち24件はgoldと最初のtokenから分岐、残り1件は位置5から分岐した。この位置を品質破綻開始とは扱わない。たとえばパスタの話に原文と異なる「そうですね。おいしいですね！」を返すことは自然な別解である。

一方、全文では自然な始まりの後の反復や、開始時からの内容逸脱を実際に確認した。

## 4. 文脈に応じた生成か

真正対別履歴で25組すべて生成文字列は変わった。しかし花火、大阪、気象、海、読書などの語の取り込みだけでは、適切な応答ができたことにならない。

rootは全75prefix/全文を読解し、独立assistantがTRAIN36/DEV39を担当した。51種類のprefix+全文があり、同一出力のcore判定を整合させた。両履歴に全文として適切な応答となる組はDEV2/13、TRAIN0/12で、DEVの2組も最小相槌等で文脈に必要な内容差を示す成功とは認定できなかった。ただし本panelは必ず異なる内容を要求する最小対テストではなく、「文脈識別正答率0%」とは解釈しない。

真正条件のgeneric-onlyはTRAIN7/12、DEV8/13。なし条件25件はすべて「こんにちは！」。同一BOS入力に同一greedyなので当然であり、固定回答検索の実装や文脈無視を証明するものではない。

新診断の自然さ、topic uptake、適切な会話行為を分離した。TRAIN担当の元contextRelevantは広い話題リンクなので、追加appropriateResponse軸と区別して保存。曖昧な短い反復等にも限界がある。独立人間盲検ではなく、TRAIN担当は絞込表示前に埋込first-departure等を一時表示したことも開示した。

既存DEV真正13件は過去R46のraw/rounded生成とprefix/全文/token/EOSすべて一致。歴史的primary採点を上書きしていない。「今はどんな感じですか」の歴史的省略許容と、新しい具体的関連性診断も別軸で保持した。

## 5. 原因の判断

Aは部分的に整合する。真正履歴でも原文の内容予測は十分でない例が多く、単なる自己生成誤差だけでは説明できない。だが原文再現の低さだけで意味理解不足や容量不足とは決めない。

Bも部分的に整合する。実際に短い自然な応答から自己反復へ入る例があり、自己履歴でgold予測も変化する。ただしgold分岐は別解で起こり得るので、counterfactual NLLだけからexposure biasが主因とはしない。

Cの強い形（文脈をほぼ使わない）は支持されない。予測も生成も反応している。一方、有用な意味制御、内容を伴う返答、全文を保つ能力は弱い。

容量・データ量/分布・目的/配分・最適化は未分離。少数次元/多ジャンルの負担、generic modeへの偏り、狭いcontext補助pool、発話形式の影響は候補。context256内の短い入力でも崩れるので長さだけが原因とは言えない。greedy以外の推論は未検証。byte alias確認も全view/Tokenizerの優劣を比較したものではない。封印TEST、未知話者/話題、知識正確性、長期対話は今回証明していない。

## 6. 次の一条件

優先するのは大規模化や新lossでなく、小規模なcontext–返答対応の学習可能性対照。固定human TRAIN64組で、正対応と、同じtoken長strata内でcontextだけを固定置換した対照を比較する。context/targetの周辺分布、同じR46 selected9500対応fullstate/Adam counter29500/RNG、既存通常返答CE、batch/target量/LR、事前固定各枝最大200更新（両枝完了なら計400更新）を共通にし、条件差は対応関係だけ。公開に採用しない使い捨て診断とする。条件差一つというのはこの小診断の二枝間を指し、診断recipe全体とR46本学習の単独要因比較ではない。今回は実行していない。

訓練組への適合と、更新に使わないTRAIN診断組の真正/wrong差・無修正全文を分ける。両枝とも暗記できるだけなら一般化未達。正対応だけが内容対応を学べれば現容量で狭い対応は可能なので資料分布/配分を優先する。両方適合できなくても容量と最適化をまだ区別せず、勾配等を確認した後の容量一軸対照へ進む。

R48全量集中のcap/閾値/係数調整は再挑戦しない。R27のFFN拡大失敗だけで容量の問題を棄却せず、資料・容量・目的を別条件で判断する。
