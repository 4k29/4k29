# 日常会話の評価形式と学習表現 — 診断メモ

これはRound29の学習条件変更ではない。モデル・データ・selector・固定生成条件はpolicy.jsonのまま。

Round28の会話TRAINは発話を改変せず改行で接続し、話者名や「友人：」「私：」を挿入しない。一方、固定日常12件のうちchat6件にはこれらの役名がある。Phase1の原文予測と、役名から適切な返答を要求する能力には差があるため、chat失敗の全てを日本語文法能力だけに帰属しない。ただしprose6件も全文意味0で長い反復があり、役名形式だけでは全失敗を説明できない。

会話DEVのteacher-forcing NLL低下は人間の前文を与えた次token予測の改善を示す。自己回帰では自分の誤りを次の入力に含むので、この指標は全文一貫性を保証しない。「そうなんですね」のような高頻度の相槌を学ぶことと、文脈に応じて話を進めることを分ける。

turn-boundary-diagnostic.jsonはTRAIN内の改行境界だけを調べた。全3viewの原文byte一致を維持しても、EOS挿入時には元のBPEpieceを分割せざるを得ない位置がある。改行数260923は対話間に挿入した269877-8975=260902個より21個多く、原発話内部の改行もある。将来の発話末実験は原JSONのutterance byte offsetsを使い、単なる全改行置換と混同しない。文末記号を追加した評価NLLで元のcanonical NLLを置き換えない。

次の評価改善候補は、保持している人間DEVからsourcePathのSHA順など文章内容に依存しない手順で文脈を固定し、役名なしの原文形式で旧新とも自由生成する追加診断。新TESTや既存ゲートの代替にはせず、原文と同じ形式でも反復するかを切り分ける。Round29では既に固定した17件と日常12件、およびhumanDEV99 NLLとRound28/29用量比較を継続する。このメモだけで新しい自由生成を実行済みとは記録しない。
