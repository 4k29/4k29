# 許諾・撤回・提供同意

公開APIは投稿者の著作権の許諾を代替しない。取得・保存・学習・再配布をそれぞれ判定し、不明は保留。`rights_gate`は4権利、一次証拠、確認日/再確認期限、帰属を要求する。権利確認後もレコード例外・個人情報・品質・分割・研究計画の確認前は正式TRAINへ昇格しない。コードの判定は法的結論の自動化ではない。

新規の同意提供方式では、提供者本人が著作権を保有する本文だけを対象とし、各発話者全員の同意が必要。第三者の返信や引用を本人の同意だけで取り込まない。目的（独自日本語モデル）、取得項目、公開再配布の有無、ライセンス、撤回方法と学習後の技術的制限、保存期間を事前提示する。単一の同意で非公開会話やセンシティブ情報を無制限に収集しない。今回、提供者への連絡・同意募集・投稿取得は行っていない。

ソース内だけの話者IDを用い、サービス横断で名寄せしない。ハッシュIDは完全匿名化でも本文の検索困難化でもない。連絡先・健康・住所等の検出漏れは人手監査と申立て経路で補う。帰属表示がライセンス上必要な場合、話者の実名公開と混同せず原典著者の指定した方法を保存する。

削除・公開範囲変更・オプトアウト申立て時は、新規処理を止め該当会話全体を隔離し、派生tokens・split・評価・学習成果の系譜を辿る。`withdrawal_plan`はソース限定で会話/話者を選び、子孫artifactの無効化計画を生成する。原文・バックアップ・Git履歴の消去、公開コピーの撤回、学習済み重みからの削除は別作業であり、このツールは実行も保証もしない。公開前の権利・個人情報確認を優先する。

ライブSNSの継続取得を将来認可する場合は、規約・サーバー条件・投稿者の許諾を記録し、有効期限内に再確認する。削除イベント・定期再照会・tombstone照合の運用が実装されるまで継続収集はNo-Go。CCの原典コーパスの新しい修正/削除申立ても別途再監査する。
