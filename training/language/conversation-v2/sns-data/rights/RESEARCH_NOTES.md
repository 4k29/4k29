# Source and rights audit — 2026-10-27 JST

This directory records a bounded, primary-source investigation; **no live SNS post was acquired**. `matrix.json` separates access, local retention, ML use and redistribution and covers the requested API/thread/rate/deletion/privacy issues. `fetch-receipt.json` records HTTP status, final URL, acquisition time and SHA256. `fetch_evidence.py` repeats only terms, documentation, schemas and publisher metadata, never post endpoints. Fetch time is a snapshot, not a guarantee that policies remain unchanged.

## Decision

- **Bluesky / Mastodon / Misskey: hold.** Public replies can technically be retrieved but no blanket third-party training/redistribution permission was established. User ownership persists. A software AGPL/MIT license or documentation CC license does not license users' posts. Mastodon.social and Misskey.io terms links returned JavaScript application shells; HTTP200 is explicitly not substantive terms verification. Instance API metadata is not a replacement for full terms or individual authors' rights.
- **X: No-Go for proposed foundation model.** Developer Agreement restrictions include “use the X API or X Content to fine-tune or train a foundation or frontier model”. No written exception, paid account or API subscription was sought.
- **Reddit: No-Go without express rightsholder permission and platform-approved use.** Data API terms 2.4 withhold ML/AI training rights without express permission. No third-party archives or post-ID rehydration workarounds were used.
- **Licensed alternatives investigated for engineering:** JMultiWOZ (human Wizard-of-Oz, CC BY-SA4.0), Multi-Relational Multi-Party Chat Corpus (selected masked human research chat, CC BY-SA4.0), and original Japanese non-synthetic OpenAssistant candidate branches (Apache2.0 publisher card). These are research crowdsourced chat / assistant-style writing, **not live SNS-derived natural posts**. Actual acquisition and admission counts belong to engineering receipts, not publisher headline statistics. JMultiWOZ has not been acquired: only a joint TRAIN/DEV/TEST archive was confirmed, and selective TRAIN metadata routes failed (jmultiwoz-selective-access.json). Privacy, semantic quality and input contracts can still prevent training even after copyright permission is established.
- **NUCC / Japanese Daily Dialogue:** hold/exclude for the proposed public training corpus. NUCC is CC BY-NC-ND4.0; this is not a claim that ND universally forbids private training, but adaptation redistribution and future assistant-service scope require clarification. JDD additionally says research only, no chatbot service and no redistribution. No raw bodies were downloaded.
- **Machine-translated Japanese OASST derivatives:** excluded even when Apache-labelled; publisher explicitly says DeepL translation. Original OASST also contains synthetic model outputs, so language alone is insufficient: require non-synthetic flags, no model name, valid original-Japanese ancestors, accepted/non-deleted records, privacy and quality review. Flags are publisher metadata, not perfect proof of human authorship.

## Technical findings that affect thread reconstruction

Bluesky's pinned post lexicon distinguishes `reply.parent` and `reply.root` strong references. The rate-limit document's 3000 requests/5 minutes applies to hosted PDS; it is **not** the AppView quota. AppView's published limit is unspecified “generous”. A redirected rate page with 316 bytes did not provide that evidence; the official documentation source did.

Mastodon defaults in the currently fetched official rate page are 300 requests/5 minutes per account and per IP; the page itself is last-updated2022 and actual servers can override it. Status context includes ancestors and descendants; deleted/private ancestors may be absent. No remote timeline request was made.

Misskey source `notes/children` returns direct replies **or quoted renotes**. Treating all returned children as correct replies would fabricate training relationships. `notes/conversation` follows ancestors and visibility/visitor settings apply. The pinned schema limits are 1–100 items, default10; they are not requests-per-second limits. Forks and servers may differ.

MRMPC `mention_to` is an addressee list, not an exact parent pointer; three speakers cannot be silently mapped onto existing two human role tokens. JMultiWOZ preserves turn order and user/wizard identity, but adjacency is not an independent annotation of semantic correctness. OpenAssistant has true parent IDs but different human authors may write the same assistant role: preserve writer identity separately from role.

## Future consent-based SNS acquisition

Before any live-post collector is enabled, obtain an auditable grant covering each participating author and all needed ancestors, third-party quotations, retention, ML use and redistribution; verify the actual server/API agreement separately. Neither a profile hashtag nor administrator consent alone clears every reply. Do not contact authors or send messages without authorization.

Keep source-local pseudonymous IDs only; no cross-platform identity matching. Store a restricted provenance/deletion index, not profiles, follower graphs, exact locations or sensitive traits. A deletion/visibility update or verified opt-out must tombstone the original record, descendants whose usable context is lost, normalized records, token windows and subsequent manifests. Do not bridge a removed utterance to create a false adjacency. Publish a versioned removal receipt without raw text. Checkpoints trained on affected text require lineage disclosure and retraining/validated unlearning decisions; removing a JSON row does not erase learned data. Git-history persistence is also a publication risk: do not commit unreviewed personal text and do not promise universal deletion of all distributed copies.

CC BY-SA4 provides attribution, changes indication, source/license links and ShareAlike for adapted datasets; privacy/personality and third-party rights are not waived. The license is generally irrevocable while compliant, but attribution removal on request and separate legal/privacy duties still matter. Only JMultiWOZ's publisher explicitly states trained models are not dataset derivatives; do not generalize that statement to every CC corpus. Apache2 dataset reuse requires appropriate license/notice/change retention. These are project admission interpretations, not blanket conclusions about every jurisdiction.
