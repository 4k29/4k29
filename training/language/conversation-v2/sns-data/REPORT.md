# 自然な日本語会話データ：取得・構造・権利・品質の統合判断

GOAL.md、PR92〜94を継承したデータのみの研究。**ライブSNS投稿の学習許諾を確認できず、投稿取得は0。代替として許諾の明確な公開人間会話資料を実取得し、パイプライン・品質監査まで実行した。正式TRAIN採用と本学習はNo-Go。** モデル能力が向上したという結果ではない。optimizer更新、Tokenizer fit、公開モデル/サイト変更、有料API/GPU利用、マージはすべて0。

## サービスと原典の比較

2026年10月27日確認。公式規約・API・ライセンスを一次情報から調べ、URL、HTTP、取得日時、SHAを `rights/fetch-receipt.json` と証拠snapshotへ保存。12ソースの要求10項目は `rights/matrix.json`。これは本プロジェクトでの採否であり一般的な法的結論ではない。

公開候補の独立本文量は計660,087tokens。以前のRPやPR94の原文を足した数ではない。取得前/隔離前のMRMPC792,825tokens、OASST旧候補60,189→55,643tokens等は履歴であり最終量へ合算しない。全体取得のSHA・Git blob照合、公開パックのSHA、隔離理由を別に保存した。OASSTの全言語本文は永続保存せず、日本語抽出・隔離後の公開パックだけを成果物とする。

質問/相談/理由/説明等の厳密な全件genreラベルは未作成。MRMPCの原典metadataは初対面386/家族入り365で、発話内容のgenreとは異なる。自動proxyはMRMPC相槌5623/78811（7.13%）、内容長さproxy34644/78811（43.96%）。同じ規則で既存RP TRAINは相槌7446/180006（4.14%）、内容proxy152107/180006（84.50%）。発話の細かい分割・短い節がこの差に影響するため、意味的な内容率や優劣とは解釈しない。少なくとも「新資料は相槌が少ないので改善する」という仮説は支持しない。

MRMPCは全751会話が3発話以上。OASSTは2発話128枝、3発話以上154枝。MRMPCの時系列隣接78060組はすべて256以内だが、明示的な親返信確認は0。OASSTはユニーク非root441発話の親参照を確認できるが、それも意味的に適切な返答の証明ではない。日時は原典に無ければnullを保持し捏造しない。

話者/family/重複をunionしてから固定hashで分割し、今回の候補はすべてTRAIN候補側、DEV/TESTは0。MRMPCは386/365の2成分、OASSTは1成分である。MRMPCは将来事前固定で一方をheldoutにする余地はあるが、会話種別と話者の差が大きく、今回件数を稼ぐために分割を引き直していない。OASSTのtreeだけをランダム分割して執筆者独立性を偽らない。ソースをまたぐ人物同定はしておらず、同一人物の有無を保証しない。封印TESTを作成・参照したとは報告しない。

`pipeline/` に固定版取得、SHA検証、正規化比較、会話復元、重複/近重複、話者・family連結分割、日本語/相槌/宣伝/PII監査、独自BPE分析を実装した。元本文の生成AI修正・翻訳・模範返答の生成はない。本文原文と比較用canonical fingerprintを分離する。

MRMPCは時系列を確認できるが `mention_to` は宛先話者であり親投稿IDではない。`parent_id=null` を保ち、直前の発話を親だと捏造しない。3人目をBへ潰さず、原典の3話者・順序・メンションを保存した。現行2話者role3/4では全文を表せないので直接互換TRAINにはしない。原典話者profile・人口統計・家族の個人情報ファイルは取得対象外とした。

OASSTは原典parent IDを検証し、全祖先が許可対象の日本語・非synthetic・未削除・審査済みである経路だけを使用する。役割prompter/assistantと、実際の執筆者IDを別々に保持する。同じ役割を複数の執筆者が担うため「2人の会話」とは呼ばない。分岐は経路として保存するが共有祖先の反復量を別に数え、新規原文量を水増ししない。

`research/adapter_contract.py` は新しいデータ処理の参照実装であり既存学習コードを変更しない。原典開始だけBOS、真の発話境界だけEOS、窓末尾に偽EOSを足さず、同一話者の連投でもroleを反転しない。入力契約変更とデータ追加を同一の因果比較へ混ぜない。

## 品質の意味と限界

`quality/PLAN.json` の事前固定SHA標本で会話全文を読解し、個別理由を保存した。評価者はassistantであり独立した人間評価ではない。ライセンスや非syntheticという注釈も、人間執筆の完全証明ではない。自然な短い相槌、省略、絵文字等を一律削除しない。文字種の証拠が弱い短文は「日本語でない」と断定せず保留可能なflagとした。

OASSTでは具体的な返答もあるが、誤った説明、時刻や数値の捏造、モデル固有の自己紹介、不要に長い第三者引用が見つかった。権利不明の引用は会話tree単位で隔離した。原固定40件から最終隔離9件を除いた31件が今回の公開候補に対応する標本で、47返答中31返答に具体的内容を確認したが正しさの保証ではない。MRMPCは原固定40件から12件隔離後の28件（2927発話）を標本として残し、全28会話に内容のあるやり取りを確認した。途中の節・短い相槌が多く、隣接発話がすべて直接の返答ではない。補充して品質率を上げない。原40+40件とOASST補足2件の計82会話を全文読解し、追加例と旧receiptは履歴として分離した。

相槌regex・長さによる内容proxy・PII regexは分類補助であり、意味的な応答成功、bot/AI検出、個人情報の不在を保証しない。元発話の経験や属性をAI自身の事実に変える学習は避ける。人間同士の自然会話のlanguage modelingとAIとして適切な回答を学ぶ段階は区別する。

## プライバシーと権利申立て

公開パックからはPII疑いの会話全体と権利不明の長い引用treeを除き、本文をGitへ追加する前に隔離した。取得した量、公開保存した量、品質候補量、正式採用量は別に記録する。除外本文をAIで匿名化して「原文」として戻すことはしない。原SHA・除外理由・固定版取得手順を保持し、非公開の一時隔離は永続公開成果に含めない。

話者識別子はソース内だけで仮名化し、サービス横断で人物を名寄せしない。ハッシュ化は完全匿名化ではなく、原文検索や経験の記述からの特定リスクが残る。規則検出で0件でもprivacy完了とは言わない。

`governance/` の権利gateは不明を拒否し、権利確認後も正式TRAINへ昇格しない。撤回計画ツールは会話/話者と派生成果の系譜から再構築範囲を列挙する。原文消去、Git履歴の消去、公開先撤回、学習済みモデルのunlearningは実行・保証しない。将来のライブSNS収集には、投稿者全員の許諾、規約再確認、削除/公開範囲変更の反映、申立て窓口が運用可能であることが必要。今回そのcollectorは起動していない。

## 次の研究判断

今回の追加資料は、頻出相槌への偏りを診断する材料になるが、追加するだけで未知の会話への応答が改善するとは言えない。小さなOASST部分集合を大きい比率で反復すると、また少数回答の暗記や定型化になり得る。

優先するのは、現代の幅広い日本語による基盤学習と、権利・内容・話者独立性を確認した人間の返答資料の確保である。広い原文を先に学ぶ方式、混合方式、基盤後の追加学習は `research/STRATEGY.md` で比較した。現状では基盤＋別段階の内容応答を基本方針とし、忘却を防ぐ保持原文の配分は別途検証する。

最初の将来比較は、同じ11.23M初期状態・Adam/RNG・BPE・context・LR・真の有効target予算・checkpoint選択・生成条件を固定し、**権利/品質確認済みの2役割応答ソースを追加するデータ条件だけ**を比較する。今回の未採用資料をそのまま投入する設定ではない。3話者化、Tokenizer拡大、context拡大、容量拡大は別比較とする。数値予算・source比・再開監査・独立評価を固定する前には開始しない。

本文NLL、正しい/誤った文脈で固定返答を予測する差、自由生成の全文自然さ、内容必須DEV、自己生成履歴での複数ターン、反復/EOSを併用する。相槌だけ、短文終了だけ、TRAIN暗記だけでは成功としない。R25正式基準、R46科学的比較、旧17/13/9・Pareto・反復条件、R48 No-Goは維持する。

将来の収集目標は、まず独立した提供者を含む1万〜5万の内容応答会話、相談/理由/比較/説明/雑談を分けた監査標本を候補とする。量自体を合格条件にせず、既存話者との非重複と未知familyの評価を先に確保する。長期の100M以上の日本語原文と会話追加学習は別の必要量であり、今回確保済みではない。明示同意による提供窓口や、配布主体との正式な追加利用許諾がライブSNSの無許諾取得より優先される。

CPU2core/RAM8GiB/GPU0の現環境でデータ処理は実行したが、本学習の実行可能性は別。PR94の見積りはCPU約1133targets/secの旧実測、GPU throughputは未測定。100MならCPU約24.5時間/モデルの参考値であり、学習品質や工期の保証ではない。継続取得・token化・checkpoint複数世代には追加50–100GB、GPUは11M級を8–16GiB等でprofileしてから判断する。有料資源を取得していない。

## 検証と最終Go/No-Go

4担当を独立に実施した。全960原典のGit blob照合、全公開本文の話者/順序/親子と独自BPE byte復元、最終派生データのbyte一致再構築、28契約テストを通した。既存RPと公開DEV（統一32、内容24、PR94評価）を照合し、最終79,321ユニーク発話の長さ20以上のexact1件/near4件はすべてRP TRAINの一般的な挨拶、既知DEV一致0。nearは8611比較・頻出signature694skipの限定探索で、意味的独立性の証明ではない。

独自BPEの発話長p50/p90/p99はMRMPC7/14/22、OASST26/243/551tokens。文字/tokenは1.468/1.265。旧TRAIN語彙にないglyphはMRMPC94種類16057出現、OASST42種類225出現で、自作bytefallbackによりUNK欠落なく原UTF8を復元できた。これで分割が意味学習に最適だと証明したわけではない。詳細はresearch/token-length-audit.json。

| 対象 | 判断と根拠 |
|---|---|
| 許諾付き公開コーパスの取得/処理 | Go、実取得・再構築・SHA・構造監査済み |
| ライブSNSの継続取得 | No-Go、投稿者の学習/再配布許諾と削除運用が未確立 |
| 今回の候補をそのまま現v2 TRAINへ投入 | No-Go、3話者形式・未確定返信・品質/権利例外・privacy監査・未知話者評価が未解決 |
| 次期本学習 | No-Go、採用source配分と独立評価、正確な予算/保存資源/再開監査を事前固定する必要 |
| 公開モデルの置換 | No-Go、新しい学習も生成評価も実行していない |

今回確定した優先課題は、単なるSNS投稿増量ではなく、**返答の根拠と役割が明確で、話者独立性を検証でき、具体的な内容の正しさを監査した会話を増やすこと**。同意提供資料や適切な新原典で不足を埋め、既存の自然日本語基盤と分けて一条件比較を固定する。現在の66万tokens候補だけで日常会話能力を獲得できるとは判断しない。
