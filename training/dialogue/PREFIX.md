# 語頭・数値・会話の参照を改善する自作Transformer

前の自由生成モデルには、Arrayを途中から書く、17を7へ変える、最初と最後の話題やANCの条件を取り違える失敗があった。今回は自作byte BPEの語彙を訓練文章だけから作り直し、回答の書き出しの損失と、条件を文章で指定する質問・会話の教師例を改善する。Wikipedia、外部の学習済み重み・既成トークナイザー・生成API・他モデルの教師回答は使用しない。

## 文章と教師例

出典は前の実験と同じ気象庁・農林水産省50ページ、MDN30ページ、自作文章1文書。原文は65訓練・8検証・8テストの文書分割と、加工後本文のSHAを維持する。Wikipediaを新たに取得する処理はない。MDN由来の文章と要約QAは出典とCC BY-SA 4.0を保ち、詳細を [MDN-DATA-LICENSE.md](MDN-DATA-LICENSE.md) に記録する。

連続した本文を復元してから新しい自作語彙で再トークン化し、160入力トークンと16トークンの重なりで分ける。重なりは損失から除き、本文の次トークンを一度ずつ予測する。BOS/EOSは文書の本当の境界だけへ置く。長い記事に学習が偏らないよう、文書ごとの抽出確率を揃える。

AAC/LDACとANCオン/オフを文中で指定する質問、主要仕様を一段落でまとめる質問、アーティスト・曲・PC・スマートフォンなど未確認の本人情報、時刻に合う挨拶を追加した。2製品・2ドラマの先と後を、話題の順序・短い回答・詳しい回答・別の話題・お礼を変えて教える。Tecircは趣味へ含めず、好きなものだけなら名称だけ、MER/VIVANTは主演とTBSの日曜劇場だけを回答する。

データ点検で、最初の話題への質問に「前のドラマ」「前に話題にした製品」という曖昧な表現を入れていたことが判明した。初回の `prefix-corpus.json` は試行として別に残し、`prefix-corrected-corpus.json` では訓練24問・開発回帰24問を「初めに出た」「一番先に話題にした」へ訂正する。初回の重みは修正版へ流用せず、同じ設定の乱数初期化から再度学習する。訂正により語彙の頻度も変わり、7,861例のトークン列が変わるため、2候補の差を参照表現だけの因果効果と扱わない。

両候補は8,613訓練例、918検証問、928開発回帰問。数値・主演・製品仕様などの回答は、承認済み本人情報、既存の出典、Pythonの整数から作る。過去の試験問題は開発診断として扱い、今回の新しい固定問題を語彙・重み・checkpoint選択へ使わない。

## 自作語彙と学習

byte256個と制御6個を起点に、1,536回のBPE結合を自作実装で学習する。語彙は1,798、pieceは最大12 byte。訓練QAに実際に現れる識別子・整数のfragmentを出現回数の16倍追加し、英語の名称が長い日本語の句に埋もれることを減らす。既成語彙や評価問題の識別子一覧を予約する処理はない。ASCIIの数字は単位や単語と結合しない。10〜40の整数とArray・String・Set・textarea・color・font-familyが独立pieceになったことを確認する。全文の回答を一つのトークンにはしない。

`fit_fast` は隣接pairの出現位置と頻度を局所更新するheap実装。数字の境界の制約を無効にした場合は、頻度同点の順序と同じpairの左からの重複処理を含め、元の `fit` と語彙・規則が一致する。訓練MDN記事4,194文字、256結合、各3回の測定では中央値0.479秒から0.0367秒へ短縮した。これは学習中CPUでの1記事の前処理で、全コーパスや回答の速度ではない。

Transformerは3層・4 heads・96次元・MLP192・文脈容量192。訓練426,642パラメーター、本体415,584、訓練専用の対象・項目head11,058。補助headは推論で答えを選ばない。回答の最初の8トークンへ損失の重み2を掛け、残りの回答も全て学習する。質問・paddingは損失と分母から除く。原文の損失と推論はこの重み付けを使わない。既定の重み1は元の学習損失と同一であることを検査する。

学習は各候補で原文1,000更新、回答10,000更新、batch16、seed429、学習率0.0006、原文replay損失0.15、補助分類損失0.3。検証の全文一致、同点なら重み付けしないtoken損失でcheckpointを選ぶ。学習回数は実際のoptimizer更新であり、思考回数とは扱わない。

修正版のQA全文は最大142トークン、原文入力は最大160。容量192は任意の長い会話を正しく扱える証拠ではなく、位置160〜191には入力の教師信号がない。入力を切り詰めて別の質問にすることはせず、超過を記録する。

## 固定評価と会話の計算

100問は両候補の学習開始前に固定した。本人・仕様32、文脈20、未確認16、MDN定義12、比較・機種数・足し算16、会話反応4。訂正後も100問の質問・履歴・goldは全て同一で、出典データのSHAだけを再関連付けする。`prepare_prefix_controls.py` の既定動作は、保存した固定問題を変更せず再現できるかを確認する。

足し算は0〜20の入力について、同じ数の組と逆順の組を常に同じ分割へ入れる。100問の足し算8問は両順序ともQAの訓練・検証に含まれない。ただし数値と合計は他の訓練例にも現れ、この有限な問題は一般的な推論能力の証明ではない。

別に10会話31ターンを固定し、モデルが実際に出した完結した有効な回答だけを次の履歴へ追加する。正解の履歴を後から注入しない。初回では学習開始後・候補出力の確認前、修正版では学習開始前に固定した。この小さな手作成の会話も、一般的な会話の代表的調査ではない。

関連性・事実・日本語・指定の文体を各0〜2で点検し、全て2だけを合格とする。意味の等しい正しい言い換えは別に記録し、固定goldや全文一致の結果を変更しない。EOSとUTF-8の有効性は別指標にする。この点検は独立した人による評価ではない。

JavaScriptの推論では、会話のトークン列が一致する部分だけのK/V計算を再利用できるようにした。分岐した履歴は一致する直前まで戻して計算し直し、生成した回答を検索・再利用する仕組みはない。既定のdecoderは再利用を無効にし、過去の比較条件を保つ。試用CLIは有効、`--no-cache` で無効、`/reset` で履歴と状態を消去する。最大1本の会話経路を文脈容量まで保持する。入力と生成のトークン・本文・EOS・有効性が、毎回計算し直す場合と一致するか検査する。

## 初回試行の結果

初回の1,000＋10,000更新は3,118.98秒で完了し、回答9,000更新時点（実行位置10,000）を選んだ。実際には11,000更新を実行している。検証739/918、開発765/928、固定100問の全文一致52、厳しめの4項目全て合格も52。100問でEOS100、有効なトークン99、日本語のみ満点86。誤った数値や話題を、文が自然だからと合格にはしない。

前の連続文書モデルは**同じ今回の100問**で50問が一致した。初回試行では16問が新しく一致する一方、14問が一致しなくなった。前実験の別の100問での64という結果は直接比較しない。初回は挨拶4/4へ改善したが、本人/仕様21/32、文脈7/20、未確認11/16、定義3/12、比較・計算6/16。足し算は0/8である。

前モデルの不一致50件も同じ方針で点検した。「TBSの日曜劇場ドラマです」や、両作が同じ枠であることを簡潔に答えた7件は正しい言い換えなので、厳しめの合格は57/100、日本語のみ満点91、有効なトークン97である。初回試行は全文一致の2問増加を、意味・文法を含めた性能向上とは扱えない。`continuous-prefix-quality-review.json` と `prefix-quality-review.json` へ全件の点数と理由を記録し、goldは変更していない。

具体的な短い「MERは？」「なんのイヤホン使ってる？」「Headphone (1)のスペックは？」「趣味は何？」には、指定した前置きなしのまとまった回答を生成できる。しかし「MERについて、基本情報を一言で聞きたい」には別の好きなものと長い「して」の反復を返し、ANCの停止と使用を取り違え、放送枠を主演の名前と答える。識別子を語彙へ保持しても、ArrayやStringへの質問に別の話題を返す失敗は解消しない。

原文テストは8文書・88フレーム・12,085予測トークン。損失4.8521、perplexity128.01、同じ構成の乱数初期化は7.5104/1,826.89。語彙が違う前モデルと値を直接比べない。原文の検証は初期7.5076、事前学習後4.5256、対話後4.8209で、原文の保持は悪化した。QA全体の教師強制損失は訓練0.01257、検証0.27287、開発0.15569。分布の差があり、差だけで原因を断定しないが、低い訓練損失も未見の文の正しい生成を保証していない。

初回は曖昧な参照ラベルと品質の問題があるため採用しない。修正版との比較も、全体の点数だけで各項目の改善と主張しない。

## 再現手順

保存済みのコーパスと固定問題を使うと、別の入力データへ変わらない。

```sh
python training/dialogue/prepare_prefix_controls.py
PYTHONPATH=/tmp/4k29-torch-training TORCHINDUCTOR_COMPILE_THREADS=1 \
python training/dialogue/train_curriculum.py \
  --corpus training/dialogue/prefix-corrected-corpus.json \
  --pretrain-steps 1000 --steps 10000 --context 192 --dim 96 \
  --semantic-weight 0.3 --replay-weight 0.15 \
  --answer-prefix-weight 2 --answer-prefix-tokens 8 \
  --learning-rate 0.0006 --validation-every 1000 \
  --length-buckets --compile-loss \
  --checkpoint /tmp/4k29-prefix-corrected-checkpoint.pt \
  --output training/dialogue/prefix-corrected-candidate.js \
  --artifacts-prefix training/dialogue/prefix-corrected \
  --version 2026-10-05.dialogue-prefix-2
node training/dialogue/chat.mjs --question 'MERは？'
node training/dialogue/chat.mjs
```

データを作り直す場合は `prepare_prefix.py`、その修正版は `prepare_prefix.py --clarify-references`、初回の固定問題は `prepare_prefix_audit.py` と `prepare_prefix_rollouts.py`、同じ問題の修正済み出典への関連付けは `prepare_prefix_controls.py --write` を使う。問題の作成時期と学習・候補評価の順序は保存した実行記録に従う。

評価には `evaluate.py`、`evaluate_js.mjs`、`evaluate_language.py`、`evaluate_semantic.py`、`evaluate_partition_loss.py` を使い、履歴の会話は `evaluate_rollouts.mjs`、順序を交互にする測定は `benchmark_prefix_cache.mjs` へ `--model`・`--corpus`・`--out` を渡す。厳しめの点検は全不一致の理由・点数を保存したmanual-reviewを使い、`review_prefix.py --stem prefix-corrected` で再集計できる。
