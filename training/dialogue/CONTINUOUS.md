# 文書の連続処理・日本語資料・長い会話の実験

前の回答全文モデルには、文の途中で終端を出す、履歴から別の話題を選ぶ、未確認の情報に既知のプロフィールを返す失敗があった。独自のbyte BPEとcausal Transformerを継続開発し、Wikipediaを使わず、気象庁・農林水産省・MDNの日本語を学習する。外部モデルの重み、既成のトークナイザー、生成API、他モデルによる教師回答は使わない。今回も自作の乱数初期化から開始する。

## 原文と会話データ

`continuous-corpus.json` は7,017訓練例・864検証問・858開発回帰問を持つ。語彙は自作の1,286を維持し、評価文で再学習しない。機種数、主演や仕様の比較、2〜5ターンの話題参照、未確認の個人情報、16個の短いJavaScript・HTML・CSSの定義、0〜20の入力に対する足し算を追加した。回答は承認済みの本人情報・確認済みの仕様・出典に基づく説明・Pythonの整数から作り、生成AIの出力をラベルにしない。Tecircを趣味へ含めず、MER/VIVANTは主演とTBSの日曜劇場だけを説明する。

気象庁・農林水産省50ページ、MDN30ページ、自作文章1文書を、65訓練・8検証・8テスト文書へ分ける。MDN24訓練ページの加工後原文は149,378文字で、残り6ページは原文の検証・評価に使う。定義QAも訓練ページの根拠だけから作る。`const`の定義は評価用の`const`参考ページではなく、訓練用のGrammar and typesを参照する。URL・根拠段落・元と加工後のSHA・利用条件を保存し、MDN由来部分はCC BY-SA 4.0を保持する。詳細は [MDN-DATA-LICENSE.md](MDN-DATA-LICENSE.md) と `continuous-source-coverage.json`。

原文は文書全体をトークン化した後、最大192入力トークンと16トークンの重なりで分ける。BOS/EOSは実際の文書の先頭・末尾だけへ置き、文の途中を終わったことにしない。重なりは文脈として読み、損失から除く。全ての後続トークンを一度ずつ予測することと、全フレームを復元した本文のSHAを検査する。長い記事を過剰に選ばないよう、文書ごとの抽出確率を揃える。

`encode_stream` は独自BPEの規則順と重なる同一pairの左からの処理を保持するheap実装。日本語・Unicode・反復文字で元の実装と一致する。4,235文字の記事を各3回処理した測定では、元の中央値0.722秒から0.0080秒へ短縮した。これは学習中のローカルCPUでの単一記事の前処理で、推論やサイトの応答速度の測定ではない。

## 学習と生成

3層・4 heads・128次元・MLP256・文脈容量256。訓練パラメーター609,520、本体595,072、訓練専用の対象・項目head14,448。質問末尾だけを補助分類し、将来の回答はcausal maskで参照できない。補助headは推論で回答を選ばず、headを削除した生成・logitが同じになることを検査する。

原文3,000更新と対話10,000更新、計13,000更新を実行した。batch16、seed429、学習率0.0006、原文replay損失0.15、補助分類損失0.3。原文の検証損失で事前学習の状態を選び、対話では検証の全文一致、同点ならtoken損失で選ぶ。実際の実行回数と採用した重みの経路は分けて記録する。

容量256は全位置の性能を保証しない。今回の原文入力は最大192、QAの全文は最大175トークンで、位置192〜255には入力の教師信号がない。長い任意の会話を扱えるとはいえない。独立JavaScriptとPyTorchの生成上限を各入力の残り文脈長へ揃え、ragged batchの長い行だけが上限を超えてトークンを追加するバグも修正した。

```sh
python training/dialogue/prepare_continuous.py
python training/dialogue/prepare_continuous_audit.py
PYTHONPATH=/tmp/4k29-torch-training TORCHINDUCTOR_COMPILE_THREADS=1 \
python training/dialogue/train_curriculum.py \
  --corpus training/dialogue/continuous-corpus.json \
  --pretrain-steps 3000 --steps 10000 --context 256 --dim 128 \
  --semantic-weight 0.3 --replay-weight 0.15 --learning-rate 0.0006 \
  --validation-every 1000 --length-buckets --compile-loss \
  --checkpoint /tmp/4k29-continuous-checkpoint.pt \
  --output training/dialogue/continuous-candidate.js \
  --artifacts-prefix training/dialogue/continuous \
  --version 2026-10-04.dialogue-continuous-1
```

## 固定した評価と採用基準

新しい100問は訓練開始前に固定し、語彙・重み・checkpoint選択へ使わない。本人情報/仕様30、文脈12、未確認情報18、定義16、比較/機種数/足し算20、会話反応4。過去の178/38/60問は開発用と区別する。元データ・固定100問のSHAは実行記録へ保存する。

全文一致と意味・文法の評価は区別する。`continuous-review-policy.json` で、関連性・事実・日本語・指定の文体を各0〜2点にし、全て2点の回答だけを合格とする。文法が正しくても、違う製品や電池持ちの条件へ答えれば不合格。全文一致しない回答は個別に確認し、正しい言い換えを記録してもgoldを変更しない。この確認は独立した人による評価や一般的な会話能力の代表的調査ではない。

算数は**順序付きの数の組**を訓練・検証・テストへ分ける。数値自体は訓練にもあり、逆順の組が訓練に入ることもある。固定100問の足し算13問には、両順序ともテストに属する組はない。したがって、未見の数の組の計算能力を示す標本ではない。`continuous-arithmetic-audit-scope.json` へ各組と逆順の分割を記録する。原文の損失も、以前の任意chunkと今回の連続文書で構成が違うため、値を直接比較して向上とは主張しない。

## 検証・速度・公開判断

Node844/844、PyTorch7/7、公開サイトの日本語2,460/2,460。独立JavaScriptとPyTorchは開発858問・新しい100問の本文、EOS、トークン有効性が全件一致した。4参照のlogit誤差0.0002未満。補助headを削除しても生成は同一。

JavaScriptの温まった短い3問・90回は中央値6.53ms、p95 8.07ms。前実験の記録4.12msより遅く、モデル本体を大きくした効果と実行状態の差を含む。履歴を含む100問の一巡では中央値22.64ms、p95 46.04ms、最大57.53ms。開発858問では16.42ms/56.94ms/110.30ms。解析済みモデルのローカルCPU上で、取得・通信・UIを含まず、実機ブラウザーの保証ではない。前処理の高速化を回答速度の改善として数えない。

**公開サイトのモデルは置き換えない。** 学習済みの試作重み・原文処理・データ・全評価を公開し、未見の日本語へ関連した自然な回答を安定して返す当面の目標は未達とする。CPU3コア・CUDAなし、約20万文字の訓練原文と有限のQAであり、ChatGPT級の日本語・文脈・知識・推論は実現していない。回数だけを増やすより、失敗する文の構造・識別子・数の保持と、多様な会話の教師信号を改善する必要がある。
