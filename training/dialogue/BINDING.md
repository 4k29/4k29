# 質問の対象・仕様項目・条件を区別する実験

未見の質問でCMF BudsのANCを電池持ちへ取り違える、未確認の個人情報へ別のプロフィールを返す失敗を減らすため、自作の回答全文Transformerを追加開発した。外部モデルの重み・トークナイザー・生成APIは使用しない。今回のモデルは自作の乱数初期化から学習したもので、既存モデルのチェックポイントからは開始していない。

## データと学習

`prepare_binding.py` は承認済みの本人情報・一次資料で確認済みの仕様・気象庁の説明から、著者定義の質問と回答を組み立てる。製品の名前、仕様の項目、ANCやコーデックの条件、直前の製品を参照する会話、未確認の仕様を対比する。古い質問を新しい訓練例として重複追加しない。質問と履歴をトークン化した入力・質問familyが分割をまたがらないことを検査する。

5,213訓練例・544検証問・562開発回帰問。語彙は以前に訓練データだけで学習した独自byte BPEの1,286を維持し、新しい評価文で語彙を学習し直さない。原文は気象庁・農林水産省の1,249例で、今回MDNは含まない。4つの天気の定義は、訓練記事の原文を根拠に、単独で完結する短い説明を著者が定義した。URLと根拠の段落は `binding-corpus.json` のprovenanceへ保存する。

`train.py` に質問末尾の表現から対象11クラスと項目75クラスを学習する2つの補助headを加えた。回答の後続トークンを参照できないcausal maskを使用し、補助損失が共有の埋め込みとTransformerへ逆伝播する。分類headは訓練だけに使い、推論で回答の選択・挿入・検索には使わない。headを削除してもJavaScriptのlogitと生成が同じになることを検査している。

3層、4 heads、96次元、MLP192次元、文脈128。訓練パラメーター368,630（うち補助head8,342、自由生成の本体360,288）。原文1,000更新の後、対話10,000更新を実行。回答の損失へ原文を0.15、補助分類を0.3の重みで混ぜる。学習率0.0006、batch16、seed429、CPU上のPyTorch 2.6.0、所要1,463.73秒。検証の全文一致、同点ならtoken損失で選び、原文1,000＋対話9,000更新時点を採用した。実行11,000更新と採用10,000更新を区別する。

```sh
python training/dialogue/prepare_binding.py
python training/dialogue/prepare_binding_audit.py
PYTHONPATH=/tmp/4k29-torch-training TORCHINDUCTOR_COMPILE_THREADS=1 \
python training/dialogue/train_curriculum.py \
  --corpus training/dialogue/binding-corpus.json \
  --pretrain-steps 1000 --steps 10000 \
  --semantic-weight 0.3 --replay-weight 0.15 --learning-rate 0.0006 \
  --validation-every 1000 --length-buckets --compile-loss \
  --checkpoint /tmp/4k29-binding-checkpoint.pt \
  --output training/dialogue/binding-candidate.js \
  --artifacts-prefix training/dialogue/binding \
  --version 2026-10-04.dialogue-binding-1
node training/dialogue/chat.mjs --model training/dialogue/binding-candidate.js --question 'MERは？'
```

## 固定した新しい60問

`binding-audit.json` はこの学習開始前に固定した。訓練・語彙・重み選択へ使わず、以前の38問は改善の参考にしたため開発用として扱う。この60問は承認済みの事実に対する新しい聞き方を含む有限の診断で、一般会話能力の代表的な評価ではない。根拠は同じ事実であり、新しい知識を推論できることを意味しない。

| 候補 | 全文一致/60 | 本人情報・仕様/36 | 文脈/4 | 未確認情報の保留/12 | 定義/4 | 会話反応/2 | 推論/2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 以前のWeb対話のみ | 29 | 20 | 0 | 7 | 0 | 2 | 0 |
| 以前の原文replay | 31 | 21 | 1 | 7 | 0 | 2 | 0 |
| 対象・項目を学習する今回の候補 | 46 | 33 | 2 | 9 | 1 | 1 | 0 |

新しい562問では541問の厳密な全文一致、うち再利用した178問は167問。検証524/544。質問・回答の例、学習率、事前学習の出発点、補助学習をまとめて変更しており、補助headだけの因果効果を示す比較ではない。完全一致には正しい言い換えの不一致も含まれる。上表は採点後にgoldを変更していない。

失敗例は `binding-audit-results.json` に全件保存した。

- ANCを使用するCMF Budsの電池持ちを、ANCオフの8時間/35.5時間と回答する。
- kyu cameraの重量を寸法、前側の動画をストレージへ取り違える。
- TOKYO MERを紹介した履歴の後に主演を聞くと、Nothing Headphone (1)の電池持ちを返す。
- 正しい項目を説明し始めても「最大42dBのハ」でEOSを出し、文を終える。これは文脈長による切り捨てではなく、学習したモデルの早すぎる終端である。
- カメラの未確認の機種を学生の身分、現在の天気をランニングシューズと回答する。
- 平均風速の説明で語句を繰り返して文法が崩れる。挨拶とお礼を取り違える。
- イヤホンの機種数と、2つのドラマの主演の比較は正しく答えられない。

学習用headの診断では、gold回答から対象と項目が一意に分かる57問で両方正解47、対象53、項目50。正しい項目を判定しても本文を完結できない例がある。この分類結果を回答生成へ渡したり、正答率と呼んだりしない。

原文の評価120 chunk・5,488 tokenで損失5.4720、perplexity237.95。同じ語彙の以前のreplay候補5.2247/185.81より悪化した。原文の検証損失も事前学習後4.5173から5.4797へ悪化しており、日本語能力が全体として向上したとは主張しない。短い任意chunkへEOSを付ける既存の原文学習方法も、文の途中の終端を教える可能性があり、次の原文処理で改善すべき課題として残る。

## 検証と公開判断

Node831/831、補助headのcausality・出力の独立性・共有表現への勾配を確認するPyTorchテスト3/3。4つの参照logitで独立したJavaScriptとPyTorchの誤差0.0002未満、562問の生成が一致した。JavaScriptの通常生成上限をモデルの文脈長に合わせ、評価とCLIで別の96トークン上限を使うことを解消した。入力が文脈を超えれば明示的に拒否し、黙って切り詰めない。

ローカルCPU上の3つの短い質問・90回で、温まった生成の中央値4.12ms、p95 5.17ms。取得・通信・画面を含まない。語彙と本体の規模は同じで、速度の大きな改善や実機ブラウザーでの保証とは扱わない。

**公開サイトのモデルは置き換えない。** 本人情報や仕様への対応は改善したが、未見の質問へ自然で関連した回答を安定して返す当面の目標は未達成。文法、終端、条件、会話参照、未知情報、推論の失敗が残り、ChatGPT級の自然さ・知識・推論を実現したとはいえない。現在の環境はCPU3コア、CUDAなしで、広範な日本語の対話データと十分な学習資源も未整備である。これだけを失敗原因と断定しない。
