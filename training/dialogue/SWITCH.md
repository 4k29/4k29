# 新しい質問への切り替えと自然な日本語の実験

最終目標と段階は [GOAL.md](GOAL.md)。前回の [PREFIX.md](PREFIX.md) では、語頭の重み付けや数値の分割を変えても、新しい質問への汎化と実際の会話が改善しなかった。今回の中心は、前の話題への参照と、対象を明示した新しい質問の区別。以前の結果を見た問題は開発診断として扱う。

## 今回の変更

独立した自作Transformerを乱数から初期化し、原文の次トークン学習1,000更新、その後の回答学習10,000更新、計11,000更新を実行した。以前の自作重みも読み込まない。PyTorch 2.6.0+cpuは計算に使用するだけで、外部の重み・checkpoint・トークナイザー・教師生成APIは使用しない。

モデルは3層、128次元、4 heads、MLP256、文脈256、609,778パラメーター。うち生成本体は595,072、訓練専用のsubject/attribute headは14,706。headを取り除いても、logitsと生成結果は変わらない。生成時は回答一覧・プロフィール・原文を検索せず、全語彙から次のトークンを選ぶ。

12種類の完全な日本語の質問形式を訓練へ加え、残り4形式を検証2・開発テスト2へ分けた。同じ明示的な質問へ、履歴なし・異なる話題の履歴付きの例を加えた。既存の短い質問の履歴付き例は、元のfamilyの分割を保つ。ターゲットは承認済み事実・出典に基づく手書きの回答で、モデルが生成した回答を訓練用ラベルへ使わない。

`switch-corpus.json` は訓練21,721、検証2,776、開発テスト2,818問。履歴付きは順に12,039、1,724、1,756問。質問と回答の最大長は190トークン。位置190〜255へ入力を置く訓練例はなく、文脈256の設定だけで長い会話の実用性は保証しない。BPEは訓練文書・訓練QA・訓練履歴だけから新しく学習した256 byte＋1,024 merges＋6制御トークン＝1,286語彙。前回の数値境界処理を使わず、通常のBPEへ戻した。訓練に現れるASCII識別子の断片だけを追加の頻度で学習し、外部の既成語彙は使わない。

計算負荷と段階1〜3を優先し、算数のサンプル量を以前の8から0.25へ減らした。0〜20の足し算を削除したり、評価から隠したりはしない。未知の本人情報・未確認機種・仕様には不明と答えるラベルを保つ。モデル寸法、トークナイザー、語頭の重み、データとサンプリングを一緒に変えたため、結果をデータ変更だけの効果とは扱わない。

## 出典と分割

Wikipediaは使っていない。気象庁・農林水産省50ページとMDN日本語30ページ、独自の1文書＝81文書を使用。ページ単位で65訓練・8検証・8テストへ分割し、原文と加工後のSHAを保持する。訓練原文205,355字、検証16,023字、テスト16,075字。MDNの抽出文章・要約QAは [MDN-DATA-LICENSE.md](MDN-DATA-LICENSE.md) の出典・CC BY-SA 4.0を引き継ぐ。政府資料の利用条件も各manifestに保持する。

本文を変更せず新しい語彙へ再トークン化した原文windowは、訓練1,825・検証148・テスト146。重複したlookbackには損失を与えず、各文書の各targetを1度だけ数える。文書ごとの合計サンプリング量は同じで、長い文書のwindow数だけが優先されない。

checkpointの選択には、検証2,776問から訓練前に固定した512問だけを使用する。未知境界を含め、subject・attribute・履歴の層を回して選択し、IDのSHAを `switch-validation-selection.json` へ保存する。新しい120問、実会話、原文の生成結果は選択へ使わない。全2,776問の検証は選択後の診断として別に記録する。

## 新しい評価と採点

`switch-audit.json` の120問と `switch-rollouts.json` の12会話38ターンは、学習を開始する前に固定した。すべてのQA分割・以前のprobeと重複しない入力を確認する。120問の構成は本人・仕様32、文脈40、未知16、MDN16、比較・数・算数12、挨拶4。文脈40問のうち28問は、同じ質問を履歴なしでも評価する組に対応する。残り12問は作品や製品の最初／最後の参照。算数4問のoperand pairは逆順も訓練・検証から除外されている。

全文一致と、日本語・関連性・事実・文体の0〜2点を分ける。4項目がすべて2点で、終端とUTF-8が有効な場合だけ厳格合格。自然な文でも別の話題やANCの違う条件に答えれば不合格。全文不一致は1問ずつ理由を残し、gold・出力は変更しない。評価は実装アシスタントによる有限の点検で、独立した人の評価や広い日本語能力の推定ではない。

実会話はモデルが実際に生成した完全な回答を次の履歴へ渡す。正解の回答に差し替えない。不完全・無効な回答は履歴へ加えず、その手順も記録する。履歴ありの正解ラベルを与える検査と、実会話の結果を区別する。

追加の原文診断 `switch-raw-probes.json` は、既に分割済みの8つのheld-outページの各36文字をseedに、最大80トークンで文章の続きを生成する。学習開始後・今回の候補の出力を見る前に固定した。初めて生成された句点を含むpiece、EOS、予算のどれかまで、そのまま出力する。全文一致の正解ではなく、自由な日本語の文法・意味・反復の診断。引用例へ近づける修正や文法の制約は加えない。

## 生成と速度

主評価は従来のgreedy生成。追加の自作beam searchは幅4・長さ補正0.6を候補の出力を見る前に固定し、別の診断として同じ120問と実会話へ使用する。全語彙の確率を比較する近似探索で、文法・事実のmask、回答一覧、後処理の修正は使用しない。幅1では従来のgreedyの挙動をそのまま使う。幅を増やしても正しい事実や自然な文を保証しない。回答と次の履歴が変わるため、greedyとの速度差を「同じ回答を速くした」とは扱わない。

入力prefixのK/V再利用は、出力トークン・全文・EOS・有効性の一致を確認する。計時は候補の学習とPython評価を終えてから行う。実会話の1回の交互計時は順序や冷えた実行の影響を受けるため、別に複数passで実行順を入れ替えた計時も保存する。ローカルCPUの推論値で、モデルのdownload・解析・UI・通信を含むブラウザー速度ではない。


## 実行結果と公開判断

実行時間は3,374.54秒、PyTorchはCPU1 thread。CUDAは使用していない。事前学習は1,000更新の重みを選択し、回答学習は8,000更新時点（絶対step9,000）の482/512問を採用した。その後の2,000更新も実際に実行したが、検証成績が下がり、公開候補には使用していない。最後の追加学習10,000更新時点は478/512問。実行log、設定、輸出重みとrestart checkpointのSHAを保存する。

| 同じ固定問題による確認 | 以前のcontinuous / greedy | 今回のswitch / greedy | 今回のswitch / beam4 |
| --- | ---: | ---: | ---: |
| 新しい120問・全文一致 | 57/120 | 83/120 | 82/120 |
| 新しい120問・4項目すべて合格 | 59/120 | 85/120 | 84/120 |
| 日本語の項目のみ2点 | 88/120 | 117/120 | 119/120 |
| 本人・仕様の合格 | 22/32 | 24/32 | 23/32 |
| 文脈の合格 | 12/40 | 27/40 | 27/40 |
| 未知境界の合格 | 10/16 | 9/16 | 9/16 |
| MDN説明の合格 | 8/16 | 15/16 | 15/16 |
| 比較・数・算数の合格 | 7/12 | 6/12 | 6/12 |
| 挨拶の合格 | 0/4 | 4/4 | 4/4 |
| 実会話38ターン・全文一致 | 13/38 | 17/38 | 19/38 |
| 12会話の全ターン全文一致 | 0/12 | 1/12 | 1/12 |

今回のgreedyでは表現が異なる2問（67と108）を意味の同じ回答として合格にした。採点理由を全37問の全文不一致へ残している。実会話の別の厳格点検では、主演を作品名の話題として答える1問を等価として、旧13/38→新18/38、全ターン合格は0/12→1/12。beamの実会話19/38は全文一致だけの数字で、上のgreedyの18/38という厳格点検の数字と比較しない。

履歴なし／ありの同じ28問では、旧19/28→8/28、新21/28→20/28。履歴によって失った合格が11問から1問へ減り、明示的な新しい質問を区別する改善が見られた。一方、実際の生成履歴ではまだ十分に会話が成立しない。kyu cameraの重量へHeadphoneの329gを当てる、記事の問いへランニングと答える、といった混同が残る。

全文一致のQA開発テストは2,612/2,818、選択後の全検証は2,574/2,776。両方とも新しい120問とは別で、旧来の問題・ラベルを含む。全QAの教師強制損失は訓練0.14538、検証0.06586、開発テスト0.06840。訓練の先頭256行だけの損失0.00435を、全訓練データの損失とは扱わない。

原文のheld-out146windowから訓練・検証と同じ1windowを除き、145window・16,127target tokensで測ったlossは3.60868、perplexity36.9174。同じ語彙・windowの未学習初期値はloss7.18899、perplexity1,324.7672。語彙と文脈の区切りが変わるため、別の候補のperplexityとは直接比較しない。自由な文章の続きを書く8問は、旧0/8→新0/8の合格で、UTF-8などの有効性だけが6/8→7/8。**原文の損失や定型QAが良くなっても、自由な日本語の文章生成は改善できたとは言えない。**

K/V再利用は6pass×38＝228回答で全文・トークン・終端・有効性が一致し、中央値30.623→16.141ms、p95は66.997→28.980ms。中央値で約47%の計算時間減。計時は学習とPython評価を終了してから実行した。benchmarkの説明文にあった会話数10は、実測後に実際の12へ訂正した。228行の計時と一致記録は変更していない。

beam4は新しい120問の合格を1問落とし、greedyと答えも時間も変わる。3つの固定プロフィール質問ではgreedyとbeamの中央値をそれぞれ `switch-audit-js-results.json` / `switch-beam-audit-results.json` に記録する。beamでUTF-8や見た目が良くなっても、誤った仕様の条件を直せていない。既定の生成はgreedyのまま。

**この候補を公開サイトの回答モデルへ採用しない。** AAC・ANCオンへオフの80時間を答える、未確認のHeadphone (3)へHeadphone (1)のBluetoothを適用する、Buds Pro 4に455mAhを作るなど、事実と条件の誤りが残る。算数4問も0/4。段階1の自由な文章、段階3の実会話、段階4の未知境界・推論が未達で、ChatGPT同等とは扱わない。

## 学習中に届いたサイトの修正

[PR34](https://github.com/4k29/4k29/pull/34) は、今回の学習完了を待たず別に公開した。`Apple`のような固有名詞だけの入力は日本語を基本とし、直前に明示的な英語の会話があればその言語を継続する。HCI・小規模言語モデル・人や状況に合わせた情報体験は興味だけへ分類し、好きなものの一覧へ混ぜない。`Nothing Headphone (1)について詳しく教えて` は、所有の1文だけで終わらず、デザインと確認済みの仕様を段落で説明する。数値の重みはv7のままで、回答処理とcacheの版を更新した。

これらの要求が届く前に固定した試作corpusは、好きなものが4名称だけで、サイトの10名称をすべて返すことはできない。最新の所有者フィードバック4問を開発診断として別に保存した。旧・新の自由生成候補はともに必要条件0/4。新候補はAppleへ不明、好きなものへ4名称のみ、詳しいHeadphoneの問いへ重量のみ、興味の問いへ名前を返している。最新の要件へ対応したという証拠として、今回の120問の85合格を流用しない。次の学習は、最新のプロフィールの関係分類、好きなものと興味の範囲、詳細要求に合う文章のQAを先にそろえる必要がある。

公開サイトの検証は43問×文体・長さ・反復＝2,580回答と869件のCIテスト。公開ファイル36件のHTTP200とbyte一致を確認した。これは質問判定・回答の組み立ての修正の検査で、自由生成モデルの学習成果とは分ける。

## 再実行

```sh
python training/dialogue/prepare_switch.py
python training/dialogue/prepare_switch_audit.py
python training/dialogue/prepare_switch_rollouts.py
python training/dialogue/prepare_switch_raw_probes.py
python training/dialogue/train_curriculum.py \
  --corpus training/dialogue/switch-corpus.json \
  --pretrain-steps 1000 --steps 10000 --dim 128 --context 256 \
  --semantic-weight .3 --replay-weight .15 --learning-rate .0006 \
  --validation-every 1000 --validation-limit 512 --length-buckets --compile-loss \
  --checkpoint /tmp/4k29-switch-checkpoint.pt \
  --output training/dialogue/switch-candidate.js \
  --artifacts-prefix training/dialogue/switch \
  --version 2026-10-05.dialogue-switch-1
python training/dialogue/evaluate_switch.py
node training/dialogue/chat.mjs --model training/dialogue/switch-candidate.js
# 任意の追加診断。既定のgreedyとは出力も時間も異なる。
node training/dialogue/chat.mjs --model training/dialogue/switch-candidate.js --beam-size 4
```

再生成にはこのbranch内の基となるcorpus・元の評価ファイルも必要。byte列とSHAの同一性を確かめ、再生成を現在進行中の学習へ混ぜない。
